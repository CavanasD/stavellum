<h1 align="center">Stavellum</h1>

基于受支持格式的自动乐谱化与演示实用程序。

将 FL Studio 工程或 MIDI 变成滚动五线谱演示的 Windows 桌面原型。导入 **FLP / MIDI + 原曲音频**，校正乐器与记谱设置，预览并导出 **MP4、MusicXML、PDF 分谱**。

视频按 `第 n 帧的时间 = n / fps` 离线绘制，再通过 FFmpeg 编码；无需播放窗口或录屏。默认输出 1920×1080、60 fps、H.264 + AAC，优先使用 **RHI Vulkan** 帧合成及 NVIDIA NVENC 编码，设备不可用时自动回退到 CPU。

## 安装与启动

需要 Windows x64、Python **3.14**、[uv](https://docs.astral.sh/uv/) 和提供 `libx264` 编码器的 FFmpeg。Vulkan 合成需要支持 Vulkan 与 4×MSAA 的显卡驱动。源码运行时还需要 Visual Studio 的 C++ 开发工具，以构建原生 RHI 后端；Qt 开发 SDK 可由构建脚本下载到本项目缓存。PySide6 固定为 **6.11.2**，与原生后端使用的 Qt 私有 ABI 保持一致。将 `ffmpeg.exe`、`ffprobe.exe` 所在目录加入 `PATH`，然后在项目目录运行：

```powershell
uv python install 3.14
uv sync --extra dev --locked
uv run --with py7zr python scripts/build_rhi.py --prepare --install
ffmpeg -version
ffprobe -version
.\run.ps1
```

也可以运行 `uv run stavellum gui`，或用 `uv run python -m stavellum gui`。打开已有项目：

```powershell
.\run.ps1 -Project "artifacts/demo/demo.stproj"
```

先试用随代码生成的原创三乐器示例：

```powershell
uv run stavellum demo --output artifacts/demo --bars 16 --open
```

示例生成 `.stproj`、MIDI 和合成 WAV，包含普通／Pizz 奏法、长音、三连音与静默段。它用于检验软件行为，不模拟实际 FL 插件音色。

## 桌面使用流程

编辑器顶端“文件”菜单提供新建、打开、示例、选择原曲音频、保存及欢迎页入口；“导出”菜单提供 MP4 和 MusicXML / PDF 分谱导出。“更新预览”位于预览区顶部，播放与时间轴位于下方。三个设置 Tab 均按功能使用独立分组，“画面与文字”分为曲目信息、画面尺寸与谱区布局、文字位置与字号、声部动画、开场与报幕、Logo、渲染与视频编码。

1. **创建新工程**：启动后在独立的欢迎窗口选择“创建新工程”，依次选择 FLP / MIDI、原曲音频（可跳过）和五项自动处理，完成后先隐藏欢迎窗口，再显示编辑窗口。向导是独立的非模态窗口，保持在所属应用窗口上方；填写向导时可以继续编辑旧工程，提交创建时再确认未保存修改。直接打开 FLP / MIDI 也进入向导；打开保存的 `.stproj` 直接恢复工程。欢迎窗口列出最近成功打开或保存的十个工程，并提供示例入口；从编辑器的“文件 → 欢迎页”菜单可切换回欢迎窗口，再通过“返回编辑器”继续当前工程。新工程使用第一个 Arrangement，在“来源与时间”中核对诊断、Arrangement、速度与拍号；切换 Arrangement 后点“重新导入”。原曲音频应从 Song 起点导出并保留尾音，也可进入编辑器后补选。
2. **确认固定速度与拍号**。存在尚未完整识别的自动化时，FLP 会要求人工确认；确认仅表示你核实了整曲时钟，不会把实际变速工程自动转换成固定速度。
3. **校正分谱**。同一声部的普通、Pizz、Spiccato／Staccato 可合并，Violin I 与 II 保持独立。可多选分谱合并、按来源拆分、调整顺序或显式按 MIDI 通道拆分。
4. **调整乐器和图标**，新工程默认启用“使用乐器图标”，无需额外确认识别结果。可以选择内置图标、导入自定义图片，或搜索 Font Awesome 图标，按需修改谱号、调号、移调、量化、三连音、双谱表、打击乐映射与奏法。默认保守识别跳音、前倚音及音量渐变，可按分谱分别关闭；诊断列出识别数量及跳过原因。Keyswitch 只过滤你明确指定的 MIDI 音高；默认不猜测低音用途。
5. **更新预览**，播放或拖动时间轴核对谱面与声音。用“音频内乐谱零点”校准起点：例如音频的第 1.25 秒对应第一拍，填写 `1.25`；负值表示音频从乐谱中段开始。
6. **保存 `.stproj`**，然后导出 MP4 或 MusicXML / PDF。设置页可分别选择帧渲染与视频编码后端。耗时处理在后台进程执行，可查看进度并取消。成功的视频旁有 `.render.json` 统计与 `.render.log` 日志，记录实际后端、硬件、回退原因及耗时。

谱面校正不会修改原 FLP 或原曲音频；原始演奏事件与量化记谱事件分别保留。项目文件包含音符、分谱设置及输入文件引用，移动文件后可能需要重新选择音频。

“自动简化音符记法（保留调号）”默认启用，可按分谱关闭。它保留调号和实际音高，优先使用调号内的等音写法，包括 E♯、B♯、C♭、F♭：例如 C♯大调中的 F♮4 写为 E♯4，C♮4 写为 B♯3，减少多余的临时还原号。调外音沿用原记法，真正必要的还原号仍保留。预览、视频、MusicXML 和 PDF 共用结果。旧项目缺少此设置时默认启用，项目格式仍为版本 1。

“自动八度移位”默认关闭，可在新工程向导或分谱设置中开启。连续高低音区自动使用 **8va、8vb、15ma、15mb**：分别表示实际演奏比谱面高八度、低八度、高两个八度、低两个八度；双八度传统记为十五度。至少四次不同的主音起音、持续至少一个四分音符拍，且至少 60% 的起音列有同方向三条以上加线时才参与识别。移位后包括倚音在内的所有音符不超过两条加线，主音平均至少减少一条、单音最多增加一条；超过一拍的休止切断区间。单八度后仍有至少 60% 的起音列需要同方向三条以上加线时才考虑双八度。算法避免频繁切换及同谱表其他声部冲突，打击乐不参与，钢琴上下谱表分别判断。预览、视频、MusicXML 和 PDF 共用结果，原始音符、实际演奏音高、音频及活动灯时间保持不变。旧项目缺少此设置时默认关闭，已有项目明确保存的开关值继续保留，项目格式仍为版本 1。

MP4 和分谱导出会自动打开独立进度窗口。窗口显示处理步骤与耗时、实际完成帧数或分谱份数，以及当前 PDF 页数；视频还显示近 5 秒的帧/秒和相对实时速度，采样至少 1 秒后估算剩余时间和完成时刻。分谱在首份 MusicXML/PDF 保存后按平均每份耗时估算。预计时间只针对可量化的处理阶段，文件收尾耗时另计；准备、封装或长时间无进展时显示“估算中”或“正在收尾”。NVENC 回退重导会重新计算本次进度，保留累计耗时。

关闭进度窗口、按 Escape 或点“隐藏”不会取消导出，可用主窗口底部的“导出详情”重新打开。取消需点“取消导出”或“取消任务”，随后等待后台清理。成功后窗口保留结果和输出文件夹入口；隐藏的窗口保持隐藏，主窗口提示完成。失败时会提醒并保留可展开的错误详情。

原曲音频支持 WAV、FLAC、MP3、M4A、AAC、Ogg、Opus、AIFF（`.aif` / `.aiff`）和 WMA。选择器还提供“所有文件”，实际读取以 Qt 和 FFmpeg 的解码能力为准。预览直接读取原文件；无法预览时可继续无声查看谱面，项目仍保留原路径，视频导出会由 FFmpeg 尝试读取。MP4 音轨统一编码为 AAC 256 kbps，不生成中间 WAV，也不提供单独的音频导出。PCM WAV 可直接读取时长，其他音频通过 ffprobe 验证首音轨和时长；探测可取消，10 秒无结果时报告超时。

左侧活动矩形使用适度提亮的 FLP Channel Rack 通道色，激活期间整块持续亮起并隐藏边框；每次音符起音产生更亮的闪烁，在 100 毫秒内平滑回落，音符结束后仍按原力度响应衰减 120 毫秒。静音时内部为黑色，显示浅色边框。合并分谱选其普通奏法来源的颜色；多个普通来源取分谱来源顺序中的第一个，没有普通来源则取第一个来源。独立分谱各用自己来源的颜色，奏法切换不改变合并分谱的颜色；MIDI 或旧工程缺少颜色时使用白色。闪烁依据原始音符起点，跳转预览时间轴与连续播放得到相同结果。

固定头部中的谱号、调号和拍号不参与横向滚动，正文从其右侧进入。准确拍位使用单调三次时间轴；休止符的视觉中心不参与播放定位，避免挤掉其他声部的真实音符。画面相机对该时间轴做前后各最多 0.5 秒的解析平均，减轻密集音符附近的反复加减速；当前拍可在正文左侧的小范围内移动，不绘制额外播放线。窗口会自动缩短以保证拍位始终位于允许区域，音频和活动灯仍使用准确时间。乐器已显示时，持续音、未来四小节或实际可见含音小节都会保留该声部；初始隐藏的乐器等待含音小节接近实际右边界才入场。钢琴双谱表整体显隐，单乐器保持显示。

速度记号以 Leland 四分音符和 Edwin 的 `= BPM` 显示固定速度，只位于第一小节开头、首行谱表上方，与谱面一起横向滚动、同比缩放，并在左边界自然裁切离屏。它从第一帧完整显示，第一小节休止时也保留承载它的首行；离屏后回收临时留白，不重复显示。可见声部群在谱区居中，少声部自动等比例放大，最高为“基础谱面缩放”的两倍，并受谱区和固定头部空间限制。左侧活动矩形和图标随同一缩放变化，各声部保持相同尺寸；默认 1080p 在少声部放大上限时约为 26×96 像素和 60 像素。普通缩放限制其对横向滚动的扰动，可能延长至数秒或十余秒；新声部首音临近时优先保证及时显示。入场先预留空间再淡入，退场先淡出再收拢；预览、单帧和视频共享绝对展示时间排版。终止记号进入画面时，其右侧延伸五线谱为灰色，左侧保持白色。

“动画速度”下拉框提供快速、中速、慢速、极慢和自定义。中速的声部入场／退场／布局过渡基础时长为 0.35／0.25／0.35 秒，报幕淡入／淡出为 1.0／0.8 秒；快速、慢速和极慢分别使用这些时长的 0.5、2、4 倍。布局过渡以基础时长为下限，并根据滚动速度限制缩放；临近首音时会缩短声部过渡以保证音符及时出现。手动改动任一动画时长即显示自定义。预设不改变 BPM、音频速度或文字停留时间。

“动画后最短稳定时间”默认为 **2 秒**，从实际动画完成后计算，设为 **0** 可关闭。短暂隐藏后又需入场的声部会保持显示，短暂收拢和放大后又需让位的布局会合并；未来声部可以提前预留槽位，仍按实际入场条件显示。首音完整显示优先于稳定要求。该参数独立于动画速度预设，旧工程缺少此字段时使用默认值。

“开场停顿”默认为 0 秒。设置后先展示静止谱面，音频在停顿结束后与谱面滚动同步启动；左下角曲名、副标题和署名从视频零秒一起淡入，默认常驻，也可启用定时淡出。报幕完全淡出后，谱区上下边界一起平滑扩展，默认上下各留白 5%，声部相对整幅画面重新居中并逐渐放大。原谱区更宽时采用更小的对称留白，完整包含原区域；报幕可见时仍使用设置的谱区。开场停顿期间也可完成空间回收，水平谱面仍保持静止。报幕停留时间从淡入完成后计算，停顿不会自动等待淡入完成。拖动预览时间轴可直接查看停顿和淡入淡出的任意时刻。开场期间活动灯保持关闭；之后左侧矩形整体亮暗随 MIDI 活动和力度变化，音符结束后平滑衰减 120 毫秒。这是活动提示的近似，未测量原曲音频或逐轨插件的实际音量。其整块显示依据 [FL Studio Channel Rack 手册](https://www.image-line.com/fl-studio-learning-content/fl-studio-online-manual/html/channelrack.htm)。

乐谱符号统一使用 Verovio 内置的 **Leland**，缺失字形回退到 **Bravura**，覆盖预览、视频、固定谱头和分谱 PDF。曲名、副标题、作曲和编曲信息中的英文、数字与半角标点使用 **Edwin Roman**，中文及中文标点使用 **思源宋体 Regular**。奏法说明和显式斜体的乐谱指示文字使用 **Edwin Italic**，包括斜体的表情、渐变速度和文字线标签。预览、视频和 PDF 共用随包字体，无需另行安装字体；MusicXML 保留文字和字体样式，外部软件自行决定排版。乐器图标优先使用随包提供的小提琴、钢琴、键盘、鼓和铃类 SVG，缺少对应资源时使用原有图标。

## 右下角软件 Logo

设置页中的“在画面右下角显示软件 Logo”默认关闭，预览、PNG 单帧和导出视频共用此选项。启用后可选择“常驻”“淡入后常驻”或“开场淡入，停留后淡出”，并调整大小、最大不透明度及淡入／停留／淡出时长。默认大小为画面短边的 9%，最大不透明度为 0.8，淡入／停留／淡出为 1／5／0.8 秒；右边距和下边距各为画面短边的 2.5%，图片保持比例和透明背景。

Logo 从画面零秒开始计时，包含开场停顿；停留时间从淡入完成后计算，独立于报幕和动画速度预设，不延长视频。拖动时间轴、重播和导出得到相同状态。设置保存到 `.stproj`，旧工程默认关闭；修改后点击“更新预览”应用。MusicXML／PDF 分谱不添加 Logo。

黑色预览和视频画面使用 `logo-dark.png`，浅色欢迎横幅使用 `logo.png`；暗黑版无法加载时回退原版。应用及窗口图标随 Qt 检测到的系统配色切换，系统配色未知时依据应用窗口调色板判断。

## 自定义乐器图标

在“分谱校正”的图标设置旁点 **选择图标**，可以选择项目内置图标、导入 **SVG / PNG / JPEG / WebP**，或在 Font Awesome 页按英文名称搜索（例如 `guitar`、`music`），按来源和样式过滤。自定义图片保留颜色与透明度，所有图标居中等比例显示。SVG 必须自包含；引用外部图片时请先在制图软件中将图片嵌入 SVG。静态图标不会播放 SVG 动画。

应用随包提供 **Font Awesome Free 7.3.1** 的 Solid、Regular、Brands，共 2,883 个图标，离线可用。也可以点 **连接 Free / Pro 图标库**，选择自己已解压的 Font Awesome 发行包根目录、`svgs-full` 或 `svgs`。扫描按目录区分样式，支持 Pro、Sharp 和 Duotone，优先完整画布版本；双色图标使用白色与原有层透明度。目录位置跨项目记忆，可以重新扫描、取消扫描或在选中该来源后移除连接。只有选择图标时才读取其内容，不将整个用户图标库复制进项目。

选择器选中的图片和 Font Awesome 图标会嵌入 `.stproj`，重复内容只存一份。移动项目、删除原图、移除图标库目录后，已选图标仍能用于预览、PNG 单帧和 MP4。合并分谱保留首个分谱的图标，拆分及重新导入保留已有图标。MusicXML / PDF 分谱不增加图标。

也可直接输入原有图标名称（如 `violin`）或 `fa:solid:guitar`、`fa:regular:bell` 等内置 Free 名称。留空表示自动按乐器匹配；**恢复自动**清空明确选择；取消“使用乐器图标”即可隐藏图标，图标设置暂时禁用但保留选择，再次勾选便可恢复。改变乐器不会覆盖已经明确选择的图标。旧工程的确认字段会迁移为图标开关，保留原显示状态；旧“不显示”设置迁移为关闭图标并恢复自动匹配。无效图片、缺失嵌入资源或不存在的 Font Awesome 名称会明确报错。

新版继续读取旧的版本 1 项目；新保存的项目使用 `use_icon` 图标开关，需使用新版打开。用户提供的 Pro 文件保留其原有授权与署名，应用仅随包分发 Free 资源。Free 图标来源、许可和资源校验见 [第三方声明](THIRD_PARTY_NOTICES.md)。可通过 `uv run python scripts/prepare_fontawesome.py` 从固定版本的官方 npm 包复现随包资源，脚本校验上游 SHA-512 完整性。

## 制谱与预览缓存

工程打开、更新预览、PNG 单帧和视频导出共用本机制谱缓存。谱面和相机／动画时间表分别保存：内容未变时重开工程直接恢复两层；修改标题、署名、声部名称、图标、颜色、Logo、帧率或编码设置可复用两层；修改画面尺寸、谱区、缩放、动画或音频对齐时只重新计算时间表。音符、速度、拍号、量化、谱号、移调、声部组合及自动记谱设置发生变化时重新制谱。分谱 MusicXML／PDF 继续独立生成。

没有修改时再次点“更新预览”会保留当前绘图器。修改后即使已经保存工程，也仍需点击更新预览应用；保存状态与预览状态分别跟踪。更新失败或取消会保留原预览。菜单 **预览 → 强制重新制谱** 跳过两层缓存并在成功后更新缓存；**清除制谱缓存** 删除本机缓存，保留当前显示的预览。

缓存位于用户通用缓存目录中的 `Stavellum/compiled`，默认磁盘预算 **512 MiB**，按最近访问淘汰，独立于绘图器的图块内存预算。不修改 `.stproj` 格式；移动工程路径仍可复用本机已有结果，换电脑后首次打开重新制谱。缓存损坏、过期或不可读时自动重建，不可写时正常生成预览。应用编译代码、依赖版本和随包字体变化会使旧缓存失效。缓存仅保存普通数据，不保存 Qt／GPU 对象。

视频 `.render.json` 的 `compilation` 字段记录两层缓存命中状态及编译阶段耗时。开发测试可通过 `STAVELLUM_CACHE_DIR` 指定隔离目录；Python 的 `compile_scene()` 支持 `use_cache=False` 禁用读写、`force_rebuild=True` 强制重建，以及 `progress`／`cancel` 回调。冷／热编译、首帧和真实后台打开流程的测量脚本为 `scripts/verify_compilation_cache.py`，运行结果写入 `artifacts/compilation-cache/`。

## GPU 与“尽力而为”记谱

music21 / Verovio 刻谱及 SVG 图块准备仍由 CPU 完成；RHI Vulkan 负责每一帧的缩放、移动、透明度与画面合成。导出直接交付原生 BGRA 读回存储，省去额外整帧 CPU 复制；预览和单帧接口返回 RGBA。视频帧流提供可选的有限批量提交，让数帧共用一次 GPU 等待，图块工作集变化或超预算时提前结束批次，读回输出另受 64 MiB 批次预算限制。默认逐帧提交；诊断可设置 `STAVELLUM_RHI_BATCH_SIZE=2` 或 `4`。绘制与写入编码器通过两帧有界队列并行，保持帧序和图像所有权。GPU 合成统一使用 Qt QRhi Vulkan 离屏渲染，要求硬件支持 4×MSAA；无需另装 CUDA。自动模式会在 Vulkan 初始化或运行失败后切到 CPU，保持同一编码流的像素格式，重新绘制尚未交付的帧；手动指定 `gpu` 时不可用会报错。视频编码独立探测 NVENC，自动模式发生设备编码故障时从第 0 帧用 x264 重导一次；取消、音频或文件错误不会触发重导。

CPU 编码使用原有 CRF / preset；NVENC 独立使用 CQ（默认 18，1–51）和 p1–p7（默认 p5）。两种质量数值不代表完全相同的画质。图块缓存与 GPU 纹理缓存各按缓存预算限制；帧缓冲和字体缓存另占资源，统计中的缓存峰值不是整个进程内存或实际显存峰值。

正文图块按当前显示缩放选择二倍分辨率层级，保留足够精度，避免多声部时仍生成最高放大精度的整套图块。每帧先确定需要保留的图块；预算不足时，其余图块临时绘制，不淘汰本帧已保留的图块。默认预算仍为 **64 MiB**，新策略直接使用现有缓存设置。渲染报告包含图块命中、重建、淘汰、SVG 生成时间和可见图块工作集峰值；首次生成或跳转仍可能需要等待。

GPU 路径现已统一为 RHI Vulkan，预览、PNG、视频和后台导出共享同一实现；旧项目中的 `auto`、`gpu` 设置直接沿用，项目格式不变。`.render.json` 记录 Vulkan 设备、GPU 提交、同步读回、格式转换、排队、管道写入及缓冲估计；Qt 内部读回和同步等待仍有成本，阶段并行执行，耗时不能相加推算总时长。

自动识别只影响派生谱面，预览、视频、MusicXML 和 PDF 共享结果，原始演奏事件、原曲音频和活动灯时钟保持不变。明确 Staccato / Spiccato 来源生成跳音点；连续至少四次规律起音、门控约为节奏槽的 35%–65% 时，恢复常规时值并加点。短前倚音须同时满足距离、音高、力度和门控条件；正规 32/64 分短音、快速乐句、复调、拨奏、明确连奏、Slide 和未知门控保持保守。首版只识别单个前倚音，不压缩颤音、回音或多音装饰组，也不分析音频转谱。

原生 DLL 和预编译 shader 位于包内 `stavellum/native/rhi`；源码构建的缓存目录也可供本地开发使用。

FLP 音量渐变依据真实控制目标及通道到 Mixer / 总线 / Master 的路由，合成 Channel Rack 与 Mixer 音量增益；名称不参与目标判断。已验证线性、Single 曲线张力及保持模式，应用 Min/Max、编曲重复、裁切和静音。累计至少 1 dB、持续至少一个当前量化格且与可制谱音符重叠时生成渐强／渐弱发夹线，保留长音中途及跨小节的实际端点；钢琴仅在下方谱表标一次。合并声部的同时发声来源须方向一致。未知曲线、LFO、未验证映射、动态分叉或方向冲突会跳过并报告；不识别 MIDI CC 或音源内部音量参数。详见 [自动化兼容说明](docs/importing.md#音量自动化与力度渐变)。

新 MIDI 导入分别保存真实按键释放与踏板延长后的发声结束；FLP 步进触发和被裁切的门控保持未知。旧 MIDI 项目缺少按键释放信息时需重新导入才能做门控推断；旧 FLP 无步进触发诊断时按保存时长补充门控，并提示旧裁切信息无法恢复。旧 FLP 项目缺少音量自动化时提示重新导入，保留可匹配的分谱校正与设置。项目格式仍为版本 1，旧文件可读取并默认启用新识别设置；新保存的字段不保证被旧程序读取。

## 命令行

`inspect` / `import` 的 Arrangement 索引从 **0** 开始。下面的输入名称是示例，请替换为自己的文件：

```powershell
# 只读检查来源、音符数量和诊断
uv run stavellum inspect "song.flp" --arrangement 0

# 创建可在桌面校正的项目；仅在确已核实固定时钟后加确认参数
uv run stavellum import "song.flp" --audio "song.flac" --output "song.stproj" --confirm-fixed-timing

# MIDI 后备入口
uv run stavellum import "song.mid" --audio "song.wav" --output "song.stproj"

# 打开项目、输出指定音频时间的 PNG 帧
uv run stavellum gui "song.stproj"
uv run stavellum frame "song.stproj" --time 12.5 --output artifacts/frame.png

# 离线逐帧导出；尺寸/帧率覆盖只影响本次导出
uv run stavellum render "song.stproj" --output artifacts/video.mp4 --width 1920 --height 1080 --fps 60 --preset medium

# 明确选择 RHI Vulkan 合成与 NVENC；不可用时直接报错
uv run stavellum render "song.stproj" --output artifacts/gpu.mp4 --render-backend gpu --video-encoder h264_nvenc --nvenc-cq 18 --nvenc-preset p5

# 固定使用 CPU，或仅对本次命令关闭自动识别
uv run stavellum render "song.stproj" --output artifacts/cpu.mp4 --render-backend cpu --video-encoder libx264 --no-auto-staccato --no-auto-grace --no-auto-dynamics --no-auto-ottava

# 每个已启用乐器生成 MusicXML 与分页 PDF
uv run stavellum parts "song.stproj" --output artifacts/parts
```

`import`、`frame`、`render`、`parts` 均支持 `--auto-simplify-accidentals`／`--no-auto-simplify-accidentals`，统一开启／关闭所有分谱的记法简化；不指定时沿用项目中保存的逐分谱选择，新导入默认开启。`frame`、`render`、`parts` 的覆盖仅影响本次输出。

同样支持 `--auto-ottava`／`--no-auto-ottava`，统一开启／关闭所有分谱的自动八度移位；不指定时沿用项目设置，新导入默认关闭，输出命令的覆盖不写回项目。

`import` 另有 `--bpm` 覆盖速度；其他布局、动画、调号和分谱校正在桌面或 `.stproj` 中保存。`frame --time` 使用展示时间，与预览时间轴和视频帧一致：音频时间为 `max(0, 展示时间 − 开场停顿)`。“音频内乐谱零点”仍相对于原曲音频校准，不包含开场停顿。导出总时长为开场停顿加原曲音频与偏移后谱面结束的较晚者，按整帧补足；必要时补静音，保留原音频尾音。旧项目缺少新设置时使用零停顿、中速报幕和报幕常驻，已有自定义动画时长保留；旧速度显示设置被忽略，统一采用首小节滚动记号。所有命令的完整参数可用 `--help` 查看。

## 当前边界与验证

- 支持固定速度、固定拍号。MIDI 变速／变拍、Type 2、SMPTE 时钟会明确拒绝；不支持完整打谱编辑器或自动音频转谱。
- FLP 只展开所选 Arrangement 中实际放置且未静音的 Pattern；分谱身份来自 Channel Rack。未知或未验证的 Playlist 布局失败时请补充 MIDI，不能把“解析没报错”当成演奏已对照验证。
- 不运行 FL Studio 插件。Audio Clip 的实际声音由原曲音频保留；缺少 MIDI 音符的轨道需补充烘焙 MIDI。Layer、Slide、通道琶音器、插件内部生成音符、微调与自动化有诊断或支持限制，不能保证仅凭 FLP 重建全部发声细节。
- 名称识别、自动谱号／调号及量化都是建议，需要音乐判断。

支持范围与复验步骤见 [FLP / MIDI 导入说明](docs/importing.md)。

## 开发与依赖

```powershell
uv run python scripts/build_rhi.py --install
uv run pytest -q
uv run ruff check src tests scripts
uv build --wheel
```

主要流程为：导入与 `ProjectIR` → `PartMapping` → 保守识别与 music21 / Verovio 共同时序刻谱 → `CompiledScene` → RHI Vulkan / CPU 离屏合成 → FFmpeg NVENC / x264。预览与导出共用 `FrameRenderer`，水平图块缓存与 GPU 纹理缓存分别有容量上限。生成的 Windows x64 wheel 包含原生 DLL 与 shader，无需在安装后编译；源码首次运行或更新原生代码后须重新构建。当前尚未提供独立桌面安装程序。
